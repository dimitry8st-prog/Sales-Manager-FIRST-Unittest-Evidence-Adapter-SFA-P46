# План SFA-P46-UNITTEST-ADAPTER R1

Нормативные источники находятся в `02_Dmitry_SFA_P46_UNITTEST/`: CONTRACT_RU.md, TESTING_RU.md, RETURN_RU.md, INTEGRATION_RU.md и полный reference/F127_CONTRACT_RU.md. Сопровождающий план не меняет контракт.

1. Сохранить исходный ZIP, структуру и хеши 16 исходных файлов; проверить 14 protected hashes и Python 3.12.x. Отдельно сохранить фактические результаты стартерных gates, не объявляя их приёмкой реализации.
2. Реализовать только RecordingError и RecordingResult в разрешённом модуле. До запуска проверить exact builtin типы, ASCII release/suite/case ID, отдельный Unicode test_id, attempt и 0..10000 bindings; запретить повторы test_id и пар suite/case. Скопировать данные без удержания ссылок на изменяемые входные контейнеры.
3. Вести последовательный цикл по test_id, а не адресу TestCase: одновременно один active ID, одна поддержанная terminal запись и stop. Поддержать разные экземпляры с одинаковым разрешённым ID в одном корректном цикле. Нарушение навсегда блокирует выдачу records, но не поднимает RecordingError непосредственно из callback.
4. Вызывать соответствующие родительские методы TestResult через super, сохраняя счётчики, диагностику и failfast/stop. Не перехватывать неожиданные ошибки собственной реализации или родителя. Обычный Exception только из test.id() фиксирует INVALID_EXECUTION; MemoryError/KeyboardInterrupt/SystemExit распространяются.
5. Формировать новые независимые снимки из завершённых случаев, ровно семь полей, Python-сортировка suite/case. Пустой результат [], неисполненные привязки отсутствуют; снимок не запечатывает объект. Активный снимок делает объект недействительным.
6. Добавить tests/test_candidate_*.py с реальными искусственными TestCase для PASS/FAIL/ERROR/SKIP, смешанных наборов, failfast, stop, всех плохих последовательностей, неподдержанных subtests/expected/unexpected, ошибок setUpClass/tearDownClass, ID-ошибок/фатальных исключений, границ конфигурации, подклассов, снимков/попыток и сохранности входов. Не запрещать разрешённую стандартную диагностику linecache под видом no-I/O теста.
7. Первый контроль: точные CHECK_PACKAGE.py, RUN_PUBLIC_TESTS.py, RUN_CANDIDATE_TESTS.py на Python 3.12 -B; собственный gate не заменять unittest discover. Сохранить stdout/stderr, argv/cwd/interpreter, коды выхода, версии, import origins и связи требований с реальными тестами. Во внешних наборах пропуски и expectedFailure не PASS.
8. Подготовить разрешённые IMPLEMENTATION_RU.md и RETURN_REPORT_RU.md с объяснением, границами и предложением неактивной установки/отката. Подготовить PATCH.diff и проверить его применение к исходной базе; OUTPUT_SHA256.json должен явно исключать сам себя, чтобы избежать самоссылки.
9. Собрать один ZIP с единственным корнем `02_Dmitry_SFA_P46_UNITTEST_RETURN/`, исходными относительными путями и только разрешёнными добавлениями. Данные для manifest и ZIP брать из одной замороженной копии байтов.
10. Второй контроль: распаковать окончательный ZIP в чистую папку, проверить CRC/состав/хеши/защищённые файлы/патч, повторить все обязательные gates и проверить происхождение импортов. Протокол повторной проверки хранить рядом с ZIP и привязать к его SHA-256, не меняя уже проверенный архив.
11. После успешных проверок опубликовать результат в указанном GitHub-репозитории, сверить опубликованные байты и сообщить commit/SHA-256 архива/фактические проверки/ограничения. Независимая приёмка заказчиком учитывается отдельно.

Финальные выводы ограничиваются компонентом нормализации фактически полученных событий. Подключение принятого F1-27, P22/P46/P47 provenance, будущий P23 runner, installed/connected checks, production и решение о релизе не объявляются выполненными.
