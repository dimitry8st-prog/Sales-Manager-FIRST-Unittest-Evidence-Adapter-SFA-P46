## Как работает адаптер

Доверенный вызывающий код создаёт `RecordingResult(release_id=..., bindings=..., attempt=...)` и передаёт его настоящему `suite.run(result)`. Сам адаптер не запускает и не загружает тесты.

Для каждого привязанного `test_id` допустим один последовательный цикл:

`startTest` → один поддержанный итог → `stopTest`.

| Реальный callback | status | exit_code | skip_count |
|---|---|---:|---:|
| `addSuccess` | PASS | 0 | 0 |
| `addFailure` | FAIL | 1 | 0 |
| `addError` | ERROR | 1 | 0 |
| `addSkip` | SKIP | 0 | 1 |

`exit_code` — нормализованный код отдельного случая, а не фактический код завершения процесса. Стандартные диагностические поля TestResult и поведение `failfast/stop` сохраняются через родительские методы.

`records()` выдаёт новые контейнеры ровно с полями `release_id,suite_id,case_id,attempt,status,exit_code,skip_count`, сортировка по `(suite_id,case_id)`. Включаются только полностью завершённые случаи. Неисполненные привязки отсутствуют; пустой прогон даёт `[]`. Снимок не закрывает объект: можно выполнить другой ещё не начатый ID.

Нарушение порядка, неизвестный/повторный ID, повтор итога, вызов records во время активного теста или неподдержанный исход навсегда делают объект недействительным. Callbacks продолжают стандартное завершение, а `records()` поднимает `RecordingError('INVALID_EXECUTION')` без частичного результата. Ошибка конфигурации — `INVALID_CONFIGURATION`. Подтесты, expectedFailure и unexpectedSuccess не поддерживаются на этой границе.

## Воспроизводимые проверки

Python 3.12.x, только стандартная библиотека. Из корня репозитория:

```bash
cd 02_Dmitry_SFA_P46_UNITTEST
python -B CHECK_PACKAGE.py
python -B RUN_PUBLIC_TESTS.py
python -B RUN_CANDIDATE_TESTS.py
```

В Windows можно использовать `py -3.12 -B` вместо `python -B`.

CHECK_PACKAGE проверяет исходные защищённые входы и прямо сообщает, что реализация им не принималась. Публичных тестов 16. Внутренние искусственные FAIL/ERROR/SKIP нужны для проверки адаптера и не означают провал внешнего собственного теста: внешний тест обязан проверить точную запись или INVALID_EXECUTION.

Фактический основной прогон на Python 3.12.14 / Linux: **16 публичных + 49 собственных = 65 внешних тестовых методов**, все обязательные команды exit 0, пропуски и expectedFailure внешних наборов — 0. Subtests и внутренние намеренные FAIL/ERROR/SKIP не подсчитываются как отдельные успешные внешние тесты. Проверены конфигурация/границы/подклассы, настоящие вложенные TestCase, циклы и sticky invalid, super/standard fields, failfast/stop, unsupported outcomes, class fixtures, исключения id(), snapshots и отсутствие собственных эффектов.

**Повторный независимый прогон из окончательного ZIP: те же 65 тестов PASS.** В чистой папке проверены структура/CRC, все 34 записи manifest и 14 protected hashes, допустимый diff, источники импортов, имена тестов и строки карты требований, неизменность файлов после gates и повторное применение PATCH.diff. Архив после проверок сохранил исходный SHA-256.

Происхождение фактически импортируемого модуля записано в raw_logs. Код не требует установленной реализации F1-27 и не подменяет её собственной сводкой.

## Границы

Разрешено менять только `source/audit_release/unittest_evidence.py` в выданном пакете. Добавления ограничены `tests/**`, IMPLEMENTATION_RU.md, RETURN_REPORT_RU.md, raw_logs/**, OUTPUT_SHA256.json, PATCH.diff. Все остальные входы сохраняются без изменений.

Адаптер не назначает доверенность тестам, не разбирает stdout, не принимает пользовательский статус, не формирует сводку релиза и не разрешает внешние действия. Собственные I/O/сеть/БД/env/часы/случайность/дочерние процессы запрещены. Обязательная стандартная диагностика unittest, включая чтение исходных строк через linecache, разрешена контрактом; раннер не является песочницей для самих TestCase.

Для разработки достаточно замороженного интерфейса F1-27. Его реализация пока не принята и в пакет не включена. Рабочая интеграция, точный принятый F1-27, проверка плана/bindings и идентичностей среды, установка/откат и релизные решения остаются отдельными этапами интегратора.
