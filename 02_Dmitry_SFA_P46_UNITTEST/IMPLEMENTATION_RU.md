# Реализация SFA-P46-UNITTEST-ADAPTER R1

## Назначение и устройство

`RecordingResult(unittest.TestResult)` получает реальные callbacks от отдельно вызванного доверенным раннером `suite.run(result)`. Адаптер не запускает/загружает тесты, не разбирает stdout и не принимает пользовательский статус. `RecordingError(ValueError)` содержит только нормативный `.code`, а `str(error)==code`.

Конструктор проверяет exact builtin типы, ASCII release/suite/case IDs, диапазоны attempt/test_id/bindings и уникальность test_id и пары (suite_id,case_id). Допустимые привязки копируются как внутреннее отображение строк на неизменяемые пары; входные list/dict не сохраняются. Ошибка конфигурации — INVALID_CONFIGURATION.

Один последовательный цикл: `startTest → ровно один поддержанный итог → stopTest`. Привязка проверяется по значению `test.id()`, а не адресу TestCase. Завершённый итог добавляется только на корректном stopTest. Нарушения ставят необратимый флаг; callbacks не выбрасывают RecordingError, но records() затем всегда выдаёт INVALID_EXECUTION без частичного списка. records() на активном тесте тоже необратимо портит выполнение. Обычные Exception из id() нормализуются; MemoryError, KeyboardInterrupt, SystemExit и неожиданные ошибки собственной реализации/родителя не подавляются.

Все переопределённые стандартные callbacks делегируют в super: сохраняются стандартные testsRun, failures, errors, skipped, expectedFailures/unexpectedSuccesses, shouldStop, failfast и диагностика. addSubTest (даже err=None), addExpectedFailure и addUnexpectedSuccess неподдержаны и всегда портят доказательства. Ошибки setUpClass/tearDownClass не привязываются к случайному случаю. Глобальные startTestRun/stopTestRun унаследованы и не сбрасывают записи.

## Нормализация результата

| Callback | status | exit_code | skip_count |
|---|---|---:|---:|
| addSuccess | PASS | 0 | 0 |
| addFailure | FAIL | 1 | 0 |
| addError | ERROR | 1 | 0 |
| addSkip | SKIP | 0 | 1 |

exit_code — нормализованный код случая, а не код процесса. records() возвращает новый list новых dict ровно из release_id/suite_id/case_id/attempt/status/exit_code/skip_count, по порядку (suite_id,case_id). Незавершённые/неисполненные привязки отсутствуют; пустой результат — [], а не общий PASS. Снимок не запечатывает объект: можно выполнить иной ещё не начатый ID. Новая попытка требует нового экземпляра с явным attempt. Причины пропуска, исходные исключения, тесты и трассировки в records не попадают.

## Границы

Нет собственного файлового/сетевого I/O, БД, env, часов, случайности, subprocess, глобального хранилища входов или релизного решения. Обязательная диагностика родителя unittest может читать строки исходников через linecache; это прямо разрешённое исключение. Сам TestCase не является песочницей и может выполнять свои эффекты вне ответственности адаптера.

Точная реализация F1-27 пока не принята и в пакет не добавлялась. Замороженного интерфейса достаточно для разработки адаптера. Пары bindings и их соответствие принятому плану, доверие к запуску, идентичности исходников/схемы/конфигурации/тестов/среды и исходные журналы устанавливает интегратор.

## Предложение неактивной установки и отката — NOT_RUN

После отдельной приёмки интегратор сверяет точную базу и резервную копию, проверяет восстановление, затем устанавливает только audit_release/unittest_evidence.py. Подключение требует принятой точной версии F1-27, согласованных bindings/плана, журналов P22/P46/P47 и отдельного подтверждения импортируемого пути. P23 runner не нужен для данной разработки. Для нового файла неактивный откат удаляет только этот файл; для заменённого восстанавливается точная резервная версия при отсутствии последующих чужих изменений. Фактические восстановление/откат/переустановка и connected tests выполняет отдельный интегратор, здесь они NOT_RUN. Рабочие F1-26/F1-27, task_store/storage/main, схемы, права и данные не изменялись.
