# Подключение и зависимости

Новый этап: `SFA-P46-UNITTEST-ADAPTER R1`; родительский `SFA-P46/W19`. Разрешённый новый путь в целевой сборке: `audit_release/unittest_evidence.py`. До выдачи источник проверен отдельно; этот пакет не разрешает менять рабочие исходники.

Стек проекта остаётся Python/PostgreSQL/очередь/Make. Этот адаптер использует только Python 3.12 и стандартную библиотеку и не требует БД, Make или провайдеров: это осознанная граница компонента нормализации тестовых событий.

Не изменять F1-26/F1-27, `task_store.py`, `storage.py`, `main.py`, схемы, сервисы, права и рабочие данные. Владельцы исходных F1-26/F1-27 и центральной интеграции сохраняются.

Точный F1-27 интерфейс приведён полностью по-русски в `reference/F127_CONTRACT_RU.md`. В нём прямо указано: вход — записи, нормализованные по каждому тестовому случаю отдельным адаптером; функция сводки не запускает тесты. Принятие существующей реализации F1-27 не является предпосылкой разработки данного производителя записей. Для рабочего подключения необходимы: принятая точная реализация F1-27; заранее проверенный план и привязки `bindings`; точные идентичности исходников, схемы, конфигурации, тестов и среды исполнения, а также исходные журналы по P22/P46/P47. Наличие адаптера не закрывает эти обязательные проверки.

Будущий исполнитель тестов P23 может использовать этот замороженный программный интерфейс. Его будущая реализация не нужна разработчику данного адаптера: тесты вызывают настоящий `unittest` напрямую. После возврата отдельный проверяющий сверяет точный код и все тесты. Только затем отдельный интегратор устанавливает один новый файл с резервным копированием и фактическим восстановлением, фактическим откатом/переустановкой и независимой проверкой пути фактически загруженного модуля. Если файла ещё не было, неактивный откат удаляет только этот файл. Подключение в рабочую среду и полномочия запуска согласованных тестов проверяются отдельно.
